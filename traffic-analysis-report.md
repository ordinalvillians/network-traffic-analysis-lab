# Network Traffic Analysis Report

## 1. Executive Summary

This lab explored basic network traffic capture and protocol inspection using Wireshark on Kali Linux.

DNS, ICMP, and TCP traffic were observed using Wireshark display filters.

The exercise provided practical experience with packet capture, traffic filtering, and documenting network activity.

## 2. Environment

- Operating system: Kali Linux
- Virtual machine platform: VMware Workstation
- Analysis tool: Wireshark 4.6.6
- Network interface: eth0

## 3. Methodology

The lab followed these stages:

1. Inspected the available network interfaces.
2. Selected the active eth0 interface for packet capture.
3. Generated traffic using ping, nslookup, and curl.
4. Examined the captured traffic in Wireshark.
5. Applied DNS, ICMP, and TCP display filters.
6. Saved screenshots to document the exercise.

## 4. Traffic Categories Examined

### DNS

The `dns` display filter was used to isolate DNS packets.

DNS traffic is relevant to understanding domain name resolution and investigating unexpected domain lookups.

A complete analysis should record the queried domain, query type, response status, and returned records when available.

### ICMP

The `icmp` display filter was used to isolate ICMP packets.

ICMP is commonly used for network diagnostics, including echo requests and replies generated by ping.

A complete analysis should distinguish requests from replies and record whether responses were received.

### TCP

The `tcp` display filter was used to isolate TCP packets.

TCP inspection can help explain connection establishment, acknowledgement, retransmission, and termination.

A deeper analysis should examine representative packet flags, source and destination ports, and connection sequences.

## 5. Evidence and Observations

The evidence verification process confirmed that the screenshots displayed DNS, ICMP, and TCP traffic.

The screenshots are stored in the `screenshots/` directory.

The current evidence establishes that these traffic categories were captured and filtered. Exact packet counts, individual query results, TCP flag sequences, and connection success rates have not been recorded in this report.

These details should only be added after inspecting the corresponding packets.

## 6. Security Relevance

Network traffic analysis supports troubleshooting and security investigations by helping analysts understand how systems communicate.

Unexpected DNS queries may warrant investigation. Unusual ICMP patterns can provide clues during network troubleshooting. TCP connection patterns may help identify failed connections or behaviour that requires further review.

These indicators require context. Their presence alone does not prove malicious activity.

## 7. Limitations

This exercise was limited to traffic captured in a single virtual machine environment.

The findings are not representative of all network traffic, and no claim of malicious activity or confirmed security vulnerability is made.

Encrypted HTTPS application content was not decrypted as part of this exercise.

## 8. Recommendations

- Record packet details before drawing conclusions.
- Compare DNS requests with their corresponding responses.
- Examine TCP handshake and termination sequences.
- Investigate retransmissions and failed connections where present.
- Preserve evidence while avoiding unnecessary disclosure of sensitive packet data.
- Repeat the lab with additional controlled traffic scenarios.

## 9. Conclusion

This exercise developed foundational experience in packet capture and traffic filtering with Wireshark.

It established a starting point for more detailed network analysis, including TCP connection inspection, DNS investigation, and TLS metadata analysis.
